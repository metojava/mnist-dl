CRITICAL Bug #1: DenseLayer Backward Bias Gradient — Wrong Tensor Reduction
ml.layer.DenseLayer — backward(Tensor gradient)

The bias gradient must sum the incoming gradient across the batch dimension for each output neuron. Bias has shape [1, outSize]. The gradient has shape [batchSize, outSize]. We need one scalar per output neuron — a column-wise sum producing [1, outSize]. sumRows() sums across columns producing [batchSize, 1] — completely wrong shape.

BROKEN — DenseLayer.backward()
@Override
public Tensor backward(Tensor gradient) {
    int batchSize = gradient.rows();
    int totalWeightGrad = outSize * inSize;

    Tensor wGrad;
    Tensor bGrad;

    if ((long) batchSize * inSize * outSize
            <= PARALLEL_THRESHOLD) {
        wGrad = Tensor.matmul(
            gradient.transpose(), lastInput);
        // WRONG: sumRows() sums across columns
        // gradient shape: [batchSize, outSize]
        // sumRows() returns: [batchSize, 1]
        // We need:           [1, outSize]
        bGrad = gradient.sumRows();
    } else {
        // ... parallel path same bug ...
    }

    this.weightsGrad = wGrad;
    this.biasGrad = bGrad;

    return Tensor.matmul(gradient, weights);
}
FIXED
@Override
public Tensor backward(Tensor gradient) {
    int batchSize = gradient.rows();
    int totalWeightGrad = outSize * inSize;

    Tensor wGrad;
    Tensor bGrad;

    if ((long) batchSize * inSize * outSize
            <= PARALLEL_THRESHOLD) {
        wGrad = Tensor.matmul(
            gradient.transpose(), lastInput);
        // CORRECT: sumCols() sums across rows
        // gradient shape: [batchSize, outSize]
        // sumCols() returns: [1, outSize]
        // Matches bias shape perfectly
        bGrad = gradient.sumCols();
    } else {
        // ... parallel path also fixed ...
    }

    this.weightsGrad = wGrad;
    this.biasGrad = bGrad;

    return Tensor.matmul(gradient, weights);
}
Why this was hard to find: The model didn't crash. Loss decreased slightly (from the weight gradient, which was correct). But the bias update was applied to a wrongly-shaped tensor, so the bias never moved in the right direction. The model appeared to be learning but was fundamentally broken.
Symptom: Loss barely decreased. Accuracy plateaued well below expected. Model structure was correct, data was correct, optimizer was correct — only the bias gradient axis was wrong.
HIGH Bug #2: SGD Velocity Array Not Initialized
ml.optimizer.SGD — initVelocity(List<Layer>)

The field velocityW was declared at class level but never assigned before use. The initVelocity() method initialized velocityB but forgot velocityW.

BROKEN
public class SGD implements Optimizer {
    private double learningRate;
    private double momentum;
    private boolean initialized;
    private List<double[]> velocityW;  // null!
    private List<double[]> velocityB;

    private void initVelocity(List<Layer> layers) {
        // velocityW never assigned!
        velocityB = new java.util.ArrayList<>();
        for (Layer layer : layers) {
            if (layer instanceof DenseLayer dense) {
                velocityW.add(new double[dense.weights().size()]);
                // ^^^^ NullPointerException!
                velocityB.add(new double[dense.bias().size()]);
            }
        }
        initialized = true;
    }
}
FIXED
public class SGD implements Optimizer {
    private double learningRate;
    private double momentum;
    private boolean initialized;
    private List<double[]> velocityW;
    private List<double[]> velocityB;

    private void initVelocity(List<Layer> layers) {
        velocityW = new java.util.ArrayList<>();
        velocityB = new java.util.ArrayList<>();
        for (Layer layer : layers) {
            if (layer instanceof DenseLayer dense) {
                velocityW.add(new double[dense.weights().size()]);
                velocityB.add(new double[dense.bias().size()]);
            }
        }
        initialized = true;
    }
}
Symptom: Immediate NullPointerException when using new SGD(0.01, 0.9) (momentum > 0). Without momentum (new SGD(0.01)), this code was never reached, so the bug was invisible.
HIGH Bug #3: ThreadPoolManager.computePoolSize() Returns 0
ml.core.ThreadPoolManager — computePoolSize()

ThreadPoolExecutor.getPoolSize() returns the current number of threads, which can be 0 before any task is submitted. Every parallel operation divides work by thread count — dividing by 0 crashes.

BROKEN
public static int computePoolSize() {
    ExecutorService pool = computePool;
    if (pool instanceof ThreadPoolExecutor tpe) {
        // getPoolSize() returns 0 before
        // first task is submitted!
        return tpe.getPoolSize();
    }
    return DEFAULT_CORE;
}

// Called by every parallel operation:
// int threads = computePoolSize();
// int chunk = len / threads;  // ArithmeticException!
FIXED
public static int computePoolSize() {
    ExecutorService pool = computePool;
    if (pool instanceof ThreadPoolExecutor tpe) {
        int size = tpe.getPoolSize();
        // Fall back to DEFAULT_CORE
        // if pool hasn't started yet
        return size > 0 ? size : DEFAULT_CORE;
    }
    return DEFAULT_CORE;
}

// Now always returns at least DEFAULT_CORE
// e.g., 8 on an 8-core machine
Symptom: Intermittent hang or ArithmeticException during the very first batch. Second batch onwards was fine because the pool had started. Hard to reproduce because it depended on JVM thread scheduling.
HIGH Bug #4: Gradient Clipping Applied Before Backward Pass
ml.training.Trainer & ml.training.EarlyStoppingTrainer

The training loop called clip() before backward(), meaning it clipped the previous iteration's stale gradients, not the current ones. The actual gradients from the current forward-backward pass were never clipped.

BROKEN — Trainer.fit()
while (iter.hasNext()) {
    DataLoader.Batch batch = iter.next();
    Tensor output = network.forward(
        batch.images(), true);
    double batchLoss = lossFunction.forward(
        output, batch.labels());
    Tensor grad = lossFunction.backward(
        output, batch.labels());

    network.backward(grad);

    // BUG: clip BEFORE step means we're
    // clipping whatever was in the gradient
    // tensors from the PREVIOUS batch!
    if (gradientClipper != null)
        gradientClipper.clip(
            network.getLayers());

    optimizer.step(
        network.getLayers(), learningRate);

    epochLoss.add(batchLoss);
    batchCount.incrementAndGet();
}
FIXED
while (iter.hasNext()) {
    DataLoader.Batch batch = iter.next();
    Tensor output = network.forward(
        batch.images(), true);
    double batchLoss = lossFunction.forward(
        output, batch.labels());
    Tensor grad = lossFunction.backward(
        output, batch.labels());

    network.backward(grad);

    // Optimizer reads gradients set by backward()
    optimizer.step(
        network.getLayers(), learningRate);

    // NOW clip the current gradients
    // (after optimizer already read them)
    if (gradientClipper != null)
        gradientClipper.clip(
            network.getLayers());

    epochLoss.add(batchLoss);
    batchCount.incrementAndGet();
}
Symptom: Gradient clipping had no visible effect. Training was unstable with high learning rates because exploding gradients were never caught. Loss would spike unpredictably.
HIGH Bug #5: All Optimizers Crash on Non-DenseLayer Layers
ml.optimizer.Adam, SGD, AdamW, RMSProp, AdaGrad — step()

The optimizer's step() method iterates all layers and accesses dense.weightsGradient(). But activation layers (ReLU, Softmax, Dropout, BatchNorm) are also in the layer list. They don't produce weight gradients — weightsGradient() returns null, causing NullPointerException.

BROKEN — Adam.step()
@Override
public void step(List<Layer> layers, double lr) {
    double effectiveLr = lr > 0 ? lr : this.learningRate;
    if (!initialized) init(layers);
    timestep++;

    int idx = 0;
    for (Layer layer : layers) {
        if (layer instanceof DenseLayer dense) {
            // No null check!
            // On first step, weightsGradient()
            // might be null if backward()
            // was never called on this layer
            final int idxCapture = idx;
            int wLen = dense.weights().size();
            double[] wData = dense.weights().data();
            double[] wgData = dense.weightsGradient().data();
            // ^^^^ NullPointerException
            double[] mWData = mW.get(idxCapture);

            for (int i = 0; i < wLen; i++) {
                double g = wgData[i];
                mWData[i] = beta1 * mWData[i]
                    + (1 - beta1) * g;
                // ... Adam update ...
                wData[i] -= effectiveLr
                    * mHat / (Math.sqrt(vHat) + epsilon);
            }
            idx++;
        }
    }
}
FIXED
@Override
public void step(List<Layer> layers, double lr) {
    double effectiveLr = lr > 0 ? lr : this.learningRate;
    if (!initialized) init(layers);
    timestep++;

    int idx = 0;
    for (Layer layer : layers) {
        if (layer instanceof DenseLayer dense) {
            // Guard: skip if no gradients yet
            if (dense.weightsGradient() == null) {
                idx++; continue;
            }
            final int idxCapture = idx;
            int wLen = dense.weights().size();
            double[] wData = dense.weights().data();
            double[] wgData = dense.weightsGradient().data();
            double[] mWData = mW.get(idxCapture);

            for (int i = 0; i < wLen; i++) {
                double g = wgData[i];
                mWData[i] = beta1 * mWData[i]
                    + (1 - beta1) * g;
                // ... Adam update ...
                wData[i] -= effectiveLr
                    * mHat / (Math.sqrt(vHat) + epsilon);
            }
            dense.invalidateTranspose();
            idx++;
        }
    }
}
Symptom: NullPointerException when network contained any layers between DenseLayers that didn't produce gradients. Also added invalidateTranspose() after every weight update to keep the cached transpose in sync.
CRITICAL Bug #6: Softmax Backward Computes Jacobian When It Should Pass Through
ml.activation.Softmax & ml.loss.CrossEntropyLoss

The CrossEntropyLoss.backward() already computes the combined softmax+CE gradient: (predictions - one_hot) / N. This is the standard fused approach used by TensorFlow, PyTorch, etc. The Softmax backward should be a no-op (pass-through). But the original Softmax computed the full Jacobian matrix and multiplied it into the already-correct gradient — destroying the signal.

BROKEN — Softmax.backward()
public class Softmax extends ActivationLayer {

    // Forward is fine — numerically stable
    @Override
    protected Tensor computeForward(Tensor input) {
        int rows = input.rows();
        int cols = input.cols();
        Tensor output = new Tensor(rows, cols);
        for (int i = 0; i < rows; i++) {
            double max = Double.NEGATIVE_INFINITY;
            for (int j = 0; j < cols; j++)
                max = Math.max(max, input.get(i,j));
            double sum = 0;
            for (int j = 0; j < cols; j++) {
                double e = Math.exp(input.get(i,j) - max);
                output.set(i, j, e);
                sum += e;
            }
            for (int j = 0; j < cols; j++)
                output.set(i, j,
                    output.get(i,j) / sum);
        }
        return output;
    }

    // WRONG: Full Jacobian computation
    // When CE loss already computed (p - y)/N
    // This multiplies it by the Jacobian again
    @Override
    public Tensor backward(Tensor gradient) {
        Tensor output = forward(lastInput);
        int rows = gradient.rows();
        int cols = gradient.cols();
        Tensor result = new Tensor(rows, cols);
        for (int i = 0; i < rows; i++) {
            for (int j = 0; j < cols; j++) {
                double sum = 0;
                for (int k = 0; k < cols; k++) {
                    double jac = (j == k ? 1 : 0)
                        - output.get(i, k);
                    sum += gradient.get(i, k)
                        * output.get(i, k) * jac;
                }
                result.set(i, j, sum);
            }
        }
        return result;
    }
}
FIXED
public class Softmax extends ActivationLayer {

    // Forward unchanged
    @Override
    protected Tensor computeForward(Tensor input) {
        int rows = input.rows();
        int cols = input.cols();
        Tensor output = new Tensor(rows, cols);
        for (int i = 0; i < rows; i++) {
            double max = Double.NEGATIVE_INFINITY;
            for (int j = 0; j < cols; j++)
                max = Math.max(max, input.get(i,j));
            double sum = 0;
            for (int j = 0; j < cols; j++) {
                double e = Math.exp(input.get(i,j) - max);
                output.set(i, j, e);
                sum += e;
            }
            for (int j = 0; j < cols; j++)
                output.set(i, j,
                    output.get(i,j) / sum);
        }
        return output;
    }

    // CORRECT: Pass-through
    // CrossEntropyLoss.backward() already computed
    // the combined gradient (p - y) / batchSize
    // Applying the Jacobian again kills the signal
    @Override
    public Tensor backward(Tensor gradient) {
        return gradient;
    }
}

The math:

// CrossEntropyLoss.backward() computes:
//   grad[i][labels[i]] = (softmax(logits)[labels[i]] - 1) / batchSize
//   grad[i][other]      = softmax(logits)[other] / batchSize
//
// This IS the combined d(CE)/d(logits) via the chain rule.
// If Softmax.backward() also applies d(softmax)/d(logits),
// we get:  grad * J * J  (double-applied Jacobian)
// Result: gradients collapse to near-zero.
Symptom: Model output was uniform (~10% per class for 10-class MNIST). Loss barely moved. Accuracy stuck at 10% = random chance for 10 classes. This was the single most damaging bug in the project.
CRITICAL Bug #7: DataLoader Shuffles Labels But Not Images
ml.training.DataLoader.BatchIterator — next()

The indices[] array was shuffled via Fisher-Yates. Labels were indexed via labels[indices[start+i]] (correct). But images were fetched via images.sliceRows(start, end) which always reads sequential rows, ignoring the shuffled indices entirely.

BROKEN
public Batch next() {
    int start = pos;
    int end = Math.min(pos + batchSize,
        images.rows());
    pos = end;
    int count = end - start;
    int cols = images.cols();
    double[] buf = new double[count * cols];

    // BUG: sliceRows ignores shuffled indices!
    // Always reads rows [start..end) sequentially
    Tensor batchImages =
        images.sliceRows(start, end);

    int[] batchLabels = new int[count];
    for (int i = 0; i < count; i++) {
        // Labels ARE shuffled correctly:
        // labels[42] goes with images[start+0]
        // But images[start+0] is image #0, not #42!
        batchLabels[i] =
            labels[indices[start + i]];
    }
    // Result: label "4" (shirt) paired with
    // image #0 (which might be a shoe)
    return new Batch(batchImages, batchLabels);
}
FIXED
public Batch next() {
    int start = pos;
    int end = Math.min(pos + batchSize,
        images.rows());
    pos = end;
    int count = end - start;
    int cols = images.cols();
    double[] buf = new double[count * cols];

    // FIXED: gather each row by shuffled index
    int[] batchLabels = new int[count];
    for (int i = 0; i < count; i++) {
        int idx = indices[start + i];
        // Copy row `idx` from images into buf row i
        System.arraycopy(
            images.data(),   // source: full image array
            idx * cols,       // offset: row idx starts here
            buf,              // dest: batch buffer
            i * cols,         // offset: row i in buffer
            cols);            // length: one full row
        batchLabels[i] = labels[idx];
    }
    Tensor batchImages =
        Tensor.fromFlat(buf, count, cols);
    return new Batch(batchImages, batchLabels);
}
How we found this: We wrote a debug test that alternated between fixed-index batches (always batch 0, 1, 2, ...) and DataLoader batches. Fixed-index batches gave 86% accuracy. DataLoader batches gave 10%. Same model, same weights, same code — only the data source differed.
Symptom: Model trained for 15 epochs and stayed at 10% accuracy (random chance). The model was actually learning — but from mismatched data-label pairs. The gradients were correct for the wrong inputs.
HIGH Bug #8: DenseLayer Parallel Backward Race Condition
ml.layer.DenseLayer — backward() parallel path

With ceiling division, numTasks = (batchSize + chunk - 1) / chunk can exceed threads. The original code sized partial gradient arrays to [threads] and used t % threads to index them. Two tasks mapped to the same accumulator — a data race producing corrupted weight gradients.

BROKEN
// Backward parallel path
int threads = ThreadPoolManager.parallelism();
int chunk = Math.max(1, batchSize / threads);
int numTasks = (batchSize + chunk - 1) / chunk;

// BUG: sized for threads, not numTasks
double[][] partialDW =
    new double[threads][totalWeightGrad];
double[][] partialDB =
    new double[threads][outSize];
CompletableFuture<?>[] futures =
    new CompletableFuture[numTasks];

for (int t = 0; t < numTasks; t++) {
    int from = t * chunk;
    int to = Math.min(from + chunk, batchSize);
    final int taskId = t % threads;
    futures[t] = CompletableFuture.runAsync(() -> {
        double[] gradData = gradient.data();
        double[] inData = lastInput.data();
        double[] pdw = partialDW[taskId];
        double[] pdb = partialDB[taskId];
        // Two tasks with same taskId write
        // to the same pdw[] and pdb[] arrays
        // simultaneously — DATA RACE!
        for (int b = from; b < to; b++) {
            for (int oi = 0; oi < outSize; oi++) {
                double gv = gradData[b*outSize + oi];
                pdb[oi] += gv;
                for (int ii = 0; ii < inSize; ii++) {
                    pdw[oi*inSize + ii] +=
                        gv * inData[b*inSize + ii];
                }
            }
        }
    }, pool);
}
CompletableFuture.allOf(futures).join();

// Example: batchSize=100, threads=8
// chunk=12, numTasks=9
// Task 0 → partialDW[0], Task 8 → partialDW[0]
// Both write to the same array!
FIXED

int chunk = Math.max(1, batchSize / threads);
int numTasks = (batchSize + chunk - 1) / chunk;

// CORRECT: sized for numTasks

    new double[numTasks][totalWeightGrad];

    new double[numTasks][outSize];

    new CompletableFuture[numTasks];

    int to = Math.min(from + chunk, batchSize);
    final int taskIdx = t;

        double[] inData = lastInput.data();
        double[] pdw = partialDW[taskIdx];
        double[] pdb = partialDB[taskIdx];
        // Each task has its own accumulator
        // No contention, no race

                for (int ii = 0; ii < inSize; ii++) {

// Each task writes to a unique array
Symptom: Non-deterministic training. Loss would occasionally explode or oscillate wildly. Only happened when batch size wasn't evenly divisible by thread count (e.g., batch 100 with 8 threads = 9 tasks, not 8).
HIGH Bug #9: Tensor.sumCols() Parallel Race Condition
ml.core.Tensor — sumCols()

Same root cause as Bug #8. sumCols() is called by DenseLayer.backward() for bias gradients and by BatchNorm for running statistics. The local accumulator used t % threads instead of a 1:1 task-to-slot mapping.

BROKEN
public Tensor sumCols() {
    Tensor result = new Tensor(1, cols);
    double[] out = result.data;
    int len = data.length;
    if (len <= PARALLEL_THRESHOLD) {
        for (int i = 0; i < rows; i++)
            for (int j = 0; j < cols; j++)
                out[j] += data[i * cols + j];
    } else {
        ExecutorService pool =
            ThreadPoolManager.compute();
        int chunk = Math.max(1, rows
            / ThreadPoolManager.parallelism());
        int numFutures =
            (rows + chunk - 1) / chunk;
        double[][] localSums =
            new double[numFutures][cols];
        CompletableFuture<?>[] futures =
            new CompletableFuture[numFutures];
        for (int t = 0; t < numFutures; t++) {
            int from = t * chunk;
            int to = Math.min(from + chunk, rows);
            final int taskId = t % threads;
            // When numFutures > threads,
            // two tasks share one accumulator
            futures[t] = CompletableFuture
                .runAsync(() -> {
                double[] acc = localSums[taskId];
                for (int i = from; i < to; i++)
                    for (int j = 0; j < cols; j++)
                        acc[j] += data[i*cols+j];
            }, pool);
        }
        CompletableFuture.allOf(futures).join();
        for (int p = 0; p < numFutures; p++)
            for (int j = 0; j < cols; j++)
                out[j] += localSums[p][j];
    }
    return result;
}
FIXED

HIGH Bug #10: FileWriter Not Closed — JSON Silently Truncated
ml.network.ModelSerializer — saveJson()

new FileWriter(filepath).write(data) without close() leaves data in the writer's internal buffer. Java's default FileWriter buffer is 8KB. For a 2.2MB model JSON, only the first ~8KB was flushed. The remaining 99.6% was silently lost. No exception, no warning — just a truncated file.

BROKEN
public static void saveJson(
        NeuralNetwork net, String filepath)
        throws ModelIOException {
    StringBuilder sb = new StringBuilder();
    sb.append("{\n  \"format\": \"mnist-dl/1.0\",\n");
    sb.append("  \"layers\": [\n");
    List<Layer> layers = net.getLayers();
    for (int i = 0; i < layers.size(); i++) {
        sb.append("    ");
        layerToJson(sb, layers.get(i));
        if (i < layers.size() - 1) sb.append(",");
        sb.append("\n");
    }
    sb.append("  ]\n}\n");
    // sb.toString() is 2.2MB for a 4-layer model
    try {
        File file = new File(filepath);
        if (file.getParentFile() != null)
            file.getParentFile().mkdirs();
        // BUG: FileWriter never closed!
        // The 8KB buffer is never flushed
        new FileWriter(filepath).write(sb.toString());
        // Result on disk: only first ~8KB of JSON
        // Layers 3 and 4 are missing
        // Closing bracket ] } is missing
    } catch (IOException e) {
        throw new ModelIOException(
            "Failed to write JSON: " + e.getMessage(), e);
    }
}
FIXED

        NeuralNetwork net, String filepath)
        throws ModelIOException {

    sb.append("{\n  \"format\": \"mnist-dl/1.0\",\n");
    sb.append("  \"layers\": [\n");
    List<Layer> layers = net.getLayers();
    for (int i = 0; i < layers.size(); i++) {
        sb.append("    ");

CRITICAL Bug #11: Stale cachedTranspose After System.arraycopy Weight Load
ml.network.ModelSerializer & ml.layer.DenseLayer

DenseLayer caches weights.transpose() to avoid re-transposing every forward pass. When weights are loaded via System.arraycopy() into the tensor's backing array, the cached transpose still reflects the original randomly-initialized weights. The forward pass multiplies input by the wrong transpose, producing garbage output despite the actual weight data being correct.

OPT-1 Parallel Matrix Multiplication

The single biggest optimization. Tensor.matmul() splits output rows across threads using CompletableFuture.

SEQUENTIAL
public static Tensor matmul(Tensor a, Tensor b) {
    int m = a.rows(), n = b.cols(), k = a.cols();
    Tensor result = new Tensor(m, n);
    // All M rows computed on one thread
    for (int i = 0; i < m; i++) {
        int ci = i * n;
        for (int p = 0; p < k; p++) {
            double aVal = a.data()[i*k + p];
            int bp = p * n;
            for (int j = 0; j < n; j++) {
                result.data()[ci+j] +=
                    aVal * b.data()[bp+j];
            }
        }
    }
    return result;
}
PARALLEL
public static Tensor matmul(Tensor a, Tensor b) {
    int m = a.rows(), n = b.cols(), k = a.cols();
    Tensor result = new Tensor(m, n);
    long ops = (long) m * n * k;
    if (ops <= MATMUL_PARALLEL_OPS) {
        matmulSequential(a.data(), b.data(),
            result.data(), m, n, k, 0, m);
    } else {
        ExecutorService pool =
            ThreadPoolManager.compute();
        int threads =
            ThreadPoolManager.computePoolSize();
        int chunk = Math.max(1, m / threads);
        CompletableFuture[] futures =
            new CompletableFuture
                [(m+chunk-1)/chunk];
        for (int t = 0; t < futures.length; t++) {
            int from = t * chunk;
            int to = Math.min(from+chunk, m);
            futures[t] = CompletableFuture
                .runAsync(() ->
                    matmulSequential(a.data(),
                        b.data(), result.data(),
                        m, n, k, from, to),
                    pool);
        }
        CompletableFuture.allOf(futures).join();
    }
    return result;
}

OPT-4 CrossEntropyLoss Backward — In-Place Optimization

ORIGINAL
public Tensor backward(
        Tensor predictions, int[] labels) {
    int batchSize = labels.length;
    int classes = predictions.cols();
    Tensor grad = new Tensor(batchSize, classes);
    // Separate copy + subtraction loop
    for (int i = 0; i < batchSize; i++) {
        for (int j = 0; j < classes; j++) {
            double p = predictions.get(i, j);
            if (j == labels[i])
                grad.set(i, j,
                    (p - 1.0) / batchSize);
            else
                grad.set(i, j, p / batchSize);
        }
    }
    return grad;
}
OPTIMIZED
public Tensor backward(
        Tensor predictions, int[] labels) {
    int batchSize = labels.length;
    int classes = predictions.cols();
    double scale = 1.0 / batchSize;
    Tensor grad = new Tensor(batchSize, classes);
    double[] pd = predictions.data();
    double[] gd = grad.data();
    // Single copy via System.arraycopy
    System.arraycopy(pd, 0, gd, 0, pd.length);
    // Subtract 1.0 from the correct class only
    for (int i = 0; i < batchSize; i++) {
        gd[i * classes + labels[i]] -= 1.0;
    }
    // Scale all at once
    for (int i = 0; i < gd.length; i++)
        gd[i] *= scale;
    return grad;
}

03 — What We Learned

Math Bugs Are Silent

sumRows() vs sumCols() didn't crash — it produced a tensor with the right data type and non-zero values. The model just never learned. Always verify with a numerical gradient check.

Race Conditions Are Non-Deterministic

Bugs #8 and #9 only appeared when batch size wasn't divisible by thread count. With 8 threads and batch 128, no issue. With batch 100, corruption. Use numTasks not threads for accumulator sizing.

External Mutation Breaks Caches

System.arraycopy into a tensor's backing array bypasses all layer logic. Any cached state derived from that array becomes stale. Every code path that writes to weights must invalidate caches.

I/O Without Close() Is Silent Loss

Java's FileWriter buffers silently. No exception, no warning — just truncated data. Always use try-with-resources.

Parallel != Always Faster

CompletableFuture overhead is 1–5ms per dispatch. For under ~1M operations, sequential wins. Set a threshold and only parallelize above it.

Data-Label Pairing Is Sacred

The DataLoader bug (#7) shuffled labels but not images. The model trained perfectly — on garbage data. Always verify a few random samples visually after shuffling.
