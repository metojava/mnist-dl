00 — The Starting Point

We started with a flat-package Java ML library: every class in one ml package, single-threaded matrix operations, and a basic MNIST classifier. The old code ran 784→128→64→10 with SGD in about 12–16 seconds per epoch on Fashion-MNIST.

The goal: restructure into proper packages, add Java parallelism with ExecutorService, and match or beat the old single-threaded performance.

Old Architecture

All classes in one flat ml package.
Sequential matmul. No thread pools.
SGD only. No dropout/regularization.

Target Architecture

Layered packages: core, layer, activation, loss, optimizer...
Parallel matmul, element-wise, reductions via ExecutorService.
Adam optimizer, dropout, gradient clipping, weight decay.

02 — Parallelism Architecture

The parallelism model uses a centralized ThreadPoolManager with a shared compute pool sized to availableProcessors() threads.

The pattern (repeated 25+ times across the codebase):

// Every parallel operation follows this structure:
ExecutorService pool = ThreadPoolManager.compute();
int threads = ThreadPoolManager.computePoolSize();
int chunk = Math.max(1, workSize / threads);
CompletableFuture<?>[] futures = new CompletableFuture[numTasks];

for (int t = 0; t < futures.length; t++) {
    int from = t * chunk;
    int to = Math.min(from + chunk, workSize);
    futures[t] = CompletableFuture.runAsync(() -> {
        // each thread processes its chunk
        processChunk(data, from, to);
    }, pool);
}
CompletableFuture.allOf(futures).join();

Two parallelism thresholds:

ThresholdValueUsed For
PARALLEL_THRESHOLD50,000 elementsElement-wise ops, reductions, transpose
MATMUL_PARALLEL_OPS4,000,000 FLOPsMatrix multiplication (m×n×k)

03 — Bugs Found & Fixed

BUG DenseLayer bias gradient: sumRows vs sumCols

The backward pass computed the bias gradient as gradient.sumRows(), returning shape (batchSize, 1) instead of (1, outSize). The bias is shape (1, outSize), so this was a shape mismatch that produced silently wrong gradients.

// BEFORE (WRONG) — bias gradient has wrong shape
bGrad = gradient.sumRows();     // returns (batchSize, 1)

// AFTER (CORRECT) — sum across batch dimension
bGrad = gradient.sumCols();     // returns (1, outSize) ✓
This bug meant the bias was never updated correctly. Every neuron's bias gradient was a single number (sum of all samples) instead of a per-output vector. Training would still appear to work but accuracy would be 5–10% lower than it should be.

BUG SGD velocity array not initialized

When using SGD with momentum, velocityW and velocityB were declared but never initialized before being accessed. Calling velocityW.get(idx) threw a NullPointerException.

// BEFORE (NPE)
private void initVelocity(List<Layer> layers) {
    // velocityW was never assigned!
    for (Layer layer : layers) {
        if (layer instanceof DenseLayer dense) {
            velocityW.add(new double[...]);  // NPE here
        }
    }
}

// AFTER
private void initVelocity(List<Layer> layers) {
    velocityW = new ArrayList<>();   // ← initialized first
    velocityB = new ArrayList<>();   // ← initialized first
    for (Layer layer : layers) {
        if (layer instanceof DenseLayer dense) {
            velocityW.add(new double[dense.weights().size()]);
            velocityB.add(new double[dense.bias().size()]);
        }
    }
}

BUG ThreadPoolManager.computePoolSize() returning 0

On machines with unusual thread configurations, getPoolSize() could return 0, causing a division-by-zero in chunk calculations. The fix: return DEFAULT_CORE as a fallback.

// BEFORE — potential div-by-zero
public static int computePoolSize() {
    if (pool instanceof ThreadPoolExecutor tpe) {
        int size = tpe.getPoolSize();
        return size;  // could be 0!
    }
    return DEFAULT_CORE;
}

// AFTER — safe fallback
public static int computePoolSize() {
    if (pool instanceof ThreadPoolExecutor tpe) {
        int size = tpe.getPoolSize();
        return size > 0 ? size : DEFAULT_CORE;
    }
    return DEFAULT_CORE;
}

BUG Gradient clipping BEFORE backward (NPE)

The Trainer.fit() method called clip() before backward(). At that point, all gradient tensors were null, causing NullPointerException inside the clipper.

// BEFORE — gradients are null at this point
optimizer.step(network.getLayers(), learningRate);
gradientClipper.clip(network.getLayers());    // NPE!
network.backward(grad);

// AFTER — correct order: backward → clip → step
network.backward(grad);
gradientClipper.clip(network.getLayers());    // gradients exist ✓
optimizer.step(network.getLayers(), learningRate);
This same bug existed in all 3 fit() overloads and in EarlyStoppingTrainer. Four places fixed with the same reordering.

BUG Optimizer null-guard for non-Dense layers

When Dropout, ReLU, or Softmax layers appeared in the layer list, the optimizer tried to cast them to DenseLayer via instanceof. While this skipped them, a second code path accessed weightsGradient() without null-checking, crashing when gradients hadn't been computed yet.

// Added to ALL 5 optimizers (SGD, Adam, AdamW, RMSProp, AdaGrad):
if (dense.weightsGradient() == null) { idx++; continue; }

CRITICAL Softmax backward double-applying Jacobian

This was the root cause of the model not learning at all. The loss stayed at ~2.3 (= log(10) = random guessing) for every architecture and optimizer we tried.

The problem: CrossEntropyLoss.backward() already computes the combined softmax+cross-entropy gradient (predictions - one_hot) / N. Then Softmax.backward() applied the full Jacobian again, squashing all gradients toward zero.

// BEFORE — applies Jacobian J to an already-combined gradient
// Grad arrives as: (softmax_output - one_hot) / batchSize  (CORRECT combined grad)
// Softmax then computes: J * grad = J * (p - y) / N  (WRONG — double application!)
@Override
public Tensor backward(Tensor gradient) {
    for (int i = 0; i < rows; i++) {
        for (int j = 0; j < cols; j++) {
            double s = lo[offset + j];
            double sum = 0;
            for (int k = 0; k < cols; k++) {
                double sk = lo[offset + k];
                sum += gd[offset + k] * sk * ((j == k ? 1 : 0) - s);  // Jacobian multiply
            }
            rd[offset + j] = sum;
        }
    }
}

// AFTER — pass through (combined gradient is already correct)
@Override
public Tensor backward(Tensor gradient) {
    return gradient;  // CrossEntropyLoss already computed the right thing
}
Proof it was broken: A simple Dense(784→128) → ReLU → Dense(128→10) → Softmax with SGD lr=0.1, trained for 10 epochs on Fashion-MNIST, achieved 10.0% accuracy (random) and loss stuck at 2.3026.

After fix: The same network dropped loss to 0.02 in 500 steps on a fixed batch and achieved 85%+ accuracy in 10 epochs.

BUG Stale cached transpose after optimizer step

To avoid allocating a new transposed Tensor every forward pass, we added a cachedTranspose field to DenseLayer. The bug: the cache was computed once at construction and never invalidated when the optimizer modified the weights. Every forward pass after the first optimizer step used stale weights.

// Fix: invalidate cache after every weight modification
public void invalidateTranspose() {
    this.cachedTranspose = null;
}

// Lazy recomputation on next forward:
private Tensor getCachedTranspose() {
    if (cachedTranspose == null) {
        cachedTranspose = weights.transpose();
    }
    return cachedTranspose;
}

// Called in every optimizer after modifying weights AND in update():
dense.invalidateTranspose();

CRITICAL DataLoader shuffles labels but NOT images

This was the root cause of the model not learning on full dataset. The DataLoader created shuffled indices, then used them to look up labels but sliced images sequentially. Labels didn't match their images.

// BEFORE — labels shuffled, images NOT shuffled
public Batch next() {
    int start = pos;
    int end = Math.min(pos + batchSize, images.rows());
    pos = end;
    Tensor batchImages = images.sliceRows(start, end);  // sequential!
    int[] batchLabels = new int[end - start];
    for (int i = 0; i < batchLabels.length; i++)
        batchLabels[i] = labels[indices[start + i]];   // shuffled index!
    return new Batch(batchImages, batchLabels);
}

// AFTER — both images AND labels use shuffled indices
public Batch next() {
    int start = pos;
    int end = Math.min(pos + batchSize, images.rows());
    pos = end;
    int count = end - start;
    int cols = images.cols();
    double[] buf = new double[count * cols];
    int[] batchLabels = new int[count];
    for (int i = 0; i < count; i++) {
        int idx = indices[start + i];
        System.arraycopy(images.data(), idx * cols, buf, i * cols, cols);
        batchLabels[i] = labels[idx];
    }
    return new Batch(Tensor.fromFlat(buf, count, cols), batchLabels);
}
Proof it was broken: Training on 2 alternating fixed batches (same sliceRows range every time) worked perfectly — 73% accuracy in epoch 1. Training via DataLoader with shuffled indices gave 10% accuracy (random) stuck at loss 2.3 for all 5 epochs.

After fix: Same architecture achieved 86%+ accuracy in 5 epochs with the full dataset.

BUG Race condition in DenseLayer parallel backward

When futures.length > threads (ceiling division), the index mapping tid = t % threads caused two futures to share the same partial accumulator — a data race on concurrent += operations.

// BEFORE — data race when futures.length > threads
double[][] partialDW = new double[threads][totalWeightGrad];  // sized to threads
for (int t = 0; t < futures.length; t++) {
    final int tid = t % threads;  // wraps! two futures → same tid
    futures[t] = CompletableFuture.runAsync(() -> {
        double[] pdw = partialDW[tid];  // two threads write += here
        ...
    }, pool);
}
// merge loop only covers `threads` entries — misses excess futures

// AFTER — one accumulator per future, unique index
int numTasks = (batchSize + chunk - 1) / chunk;
double[][] partialDW = new double[numTasks][totalWeightGrad];  // sized to numTasks
for (int t = 0; t < numTasks; t++) {
    final int taskIdx = t;  // unique per future, no modulo
    futures[t] = CompletableFuture.runAsync(() -> {
        double[] pdw = partialDW[taskIdx];  // each thread has its own array
        ...
    }, pool);
}
// merge loop covers all numTasks entries

BUG Race condition in Tensor.sumCols() (same pattern)

The same t % parallelism pattern existed in Tensor.sumCols(), used for bias gradient computation and BatchNorm.

// BEFORE — same race pattern
int parallelism = ThreadPoolManager.parallelism();
double[][] localSums = new double[parallelism][cols];
final int tid = t % parallelism;  // wraps when futures.length > parallelism

// AFTER — sized to numFutures, unique indices
int numFutures = (rows + chunk - 1) / chunk;
double[][] localSums = new double[numFutures][cols];  // one per future
final int taskIdx = t;  // direct index, no modulo

04 — Performance Optimizations

OPT Cached transposed weights

Every forward pass called weights.transpose(), allocating a new Tensor + copying the entire weight array. With batch size 256 and 4 Dense layers, that's ~936 unnecessary Tensor allocations per epoch.

Solution: Cache the transpose, recompute lazily only when weights change. Reduces GC pressure significantly.

OPT Parallel Adam optimizer

Adam's parameter update loop iterated over ~242K weights sequentially. With ThreadPoolManager.parallelFor(), it splits across all cores.

// BEFORE — fully sequential
for (int i = 0; i < dense.weights().size(); i++) {
    double g = dense.weightsGradient().data()[i];
    mW.get(idx)[i] = beta1 * mW.get(idx)[i] + (1 - beta1) * g;
    vW.get(idx)[i] = beta2 * vW.get(idx)[i] + (1 - beta2) * g * g;
    double mHat = mW.get(idx)[i] / bc1;
    double vHat = vW.get(idx)[i] / bc2;
    dense.weights().data()[i] -= effectiveLr * mHat / (Math.sqrt(vHat) + epsilon);
}

// AFTER — parallel across all cores + local variable caching
double[] mWData = mW.get(idxCapture);
double[] vWData = vW.get(idxCapture);
double invBc1 = 1.0 / bc1;   // precompute division
double invBc2 = 1.0 / bc2;

ThreadPoolManager.parallelFor(0, wLen, i -> {
    double g = wgData[i];
    mWData[i] = beta1 * mWData[i] + (1 - beta1) * g;
    vWData[i] = beta2 * vWData[i] + (1 - beta2) * g * g;
    double mHat = mWData[i] * invBc1;   // multiply instead of divide
    double vHat = vWData[i] * invBc2;
    wData[i] -= effectiveLr * mHat / (Math.sqrt(vHat) + epsilon);
});

Also replaced Math.pow(beta, timestep) with precomputed 1.0 / bc multiplications, and cached array references in local variables to avoid repeated ArrayList.get() indirection.

OPT ReLU/Dropout backward: avoid zero-fill allocation

The old backward paths called Tensor.zeros() then looped over every element. The optimized versions allocate the output directly and fill in one pass:

// BEFORE — allocates zeroed tensor, then overwrites most elements
public Tensor backward(Tensor gradient) {
    Tensor result = Tensor.zeros(lastInput.rows(), lastInput.cols());
    for (int i = 0; i < len; i++)
        result.data()[i] = lastInput.data()[i] > 0 ? gradient.data()[i] : 0;
    return result;
}

// AFTER — single allocation, single pass, no zero-fill
public Tensor backward(Tensor gradient) {
    int len = lastInput.size();
    Tensor result = new Tensor(lastInput.rows(), lastInput.cols());
    double[] in = lastInput.data();
    double[] g = gradient.data();
    double[] r = result.data();
    for (int i = 0; i < len; i++)
        r[i] = in[i] > 0 ? g[i] : 0;
    return result;
}

OPT CrossEntropyLoss.backward: avoid predictions.copy()

// BEFORE — creates an unnecessary copy of the entire predictions tensor
Tensor grad = predictions.copy();
for (int i = 0; i < batchSize; i++)
    grad.data()[i * classes + labels[i]] -= 1.0;
grad.multiplyInPlace(1.0 / batchSize);

// AFTER — single allocation, direct array write
Tensor grad = new Tensor(batchSize, classes);
System.arraycopy(pd, 0, gd, 0, pd.length);
for (int i = 0; i < batchSize; i++)
    gd[i * classes + labels[i]] -= 1.0;
for (int i = 0; i < gd.length; i++) gd[i] *= scale;

OPT Softmax backward: O(n²) → O(1) pass-through

The original Softmax backward was an O(rows × cols ²) Jacobian multiplication. After fixing the CrossEntropyLoss integration, it became a simple pass-through — zero computation, zero allocation:

@Override
public Tensor backward(Tensor gradient) {
    return gradient;  // zero-cost
}

OPT Store parameters as float[] instead of double[]

Every tensor in the library stores float[] rather than double[]. The GEMM kernels are memory-bandwidth bound, so halving the element width roughly halves the bytes moved per multiply-accumulate and lets twice as many values fit in each cache level. Hot loops keep accumulation in float (SIMD-friendly); transcendental activations still evaluate in double for range safety.

OPT Hand-blocked GEMM kernels

Profiling the 4-layer model showed ~94% of CPU time inside two matrix kernels. Both were rewritten with explicit register blocking so the innermost loop performs only load / broadcast / multiply-add:

// gemmRows (C = A*B): cache-block over (j, k) + 8-wide register unroll
final int JC = 32, KC = 128;
for (int jj = 0; jj < p; jj += JC) {         // j-tile
  for (int kk = 0; kk < n; kk += KC) {       // k-tile
    for (int i = r0; i < r1; i++) {
      for (int j = 0; j + 8 <= jLen; j += 8) {
        float c0..c7 = 0;
        for (int k = kk; k < kEnd; k++) {
          float a = ad[aRow + k];
          c0 += a*bd[bRow]; c1 += a*bd[bRow+1]; ... c7 += a*bd[bRow+7];
        }
        rd[resultRow+j] += c0; ... rd[resultRow+j+7] += c7;
      }
    }
  }
}
// matmulTransposedA (C = A^T*B, used for dW): 4×4 register micro-kernel over k
for (int k = ib; k < kEnd; k++) {           // KB = 256 k-block
  float a0..a3 = ad[k*n + i .. +3];         // 4 rows of A
  float b0..b3 = bd[k*p + j .. +3];         // 4 contiguous cols of B
  c00 += a0*b0; c01 += a0*b1; c02 += a0*b2; c03 += a0*b3;
  c10 += a1*b0; ...                          // 16 FMAs per k
}
// each rd element is accumulated in a register over the whole k range and written once
Result: the heavy 4-layer Adam epoch dropped from 11.4s to ~9s from register blocking alone (before SIMD).

OPT Activation float loops + reusable buffers

All activations previously used input.apply(x -> ...), which allocated a fresh tensor on every forward pass and paid a lambda dispatch per element. They were rewritten as direct float loops with cached output/gradient buffers sized to the input (re-allocated only when the shape changes). Applies to ReLU, Softmax, Sigmoid, Tanh, ELU, GELU, HardSwish, LeakyReLU, LogSigmoid, Mish, PReLU, Selu, Softplus and Swish.

// BEFORE — allocation + DoubleUnaryOperator per element
protected Tensor computeForward(Tensor input) {
    return input.apply(x -> 1.0 / (1.0 + Math.exp(-x)));
}

// AFTER — cached buffer, direct float loop
protected Tensor computeForward(Tensor input) {
    if (outputBuffer == null || dims changed) outputBuffer = new Tensor(rows, cols);
    float[] in = input.data(), out = outputBuffer.data();
    for (int i = 0; i < out.length; i++) {
        double x = in[i];
        out[i] = (float) (1.0 / (1.0 + Math.exp(-x)));
    }
    return outputBuffer;
}

OPT SIMD GEMM via the Vector API (~2×)

The biggest win. The JDK 17 incubator Vector API (jdk.incubator.vector) exposes FloatVector mapped to AVX2 (8 floats/lane). Both GEMM kernels were given a SIMD path that keeps the exact same loop blocking and accumulation order as the scalar code, so results are bit-for-bit identical (verified: maxerr = 0 across all shapes).

FloatVector c = FloatVector.zero(SPECIES);
for (int k = kk; k < kEnd; k++) {
    float a = ad[aRow + k];
    FloatVector bv = FloatVector.fromArray(SPECIES, bd, k*p + jj + j);  // 8 contiguous
    c = bv.mul(a).add(c);                                              // broadcast-multiply-add
}
FloatVector.fromArray(SPECIES, rd, resultRow + j).add(c).intoArray(rd, resultRow + j);

The SIMD kernels live in VectorGemm and are loaded reflectively by Tensor: if the module is unavailable the library silently falls back to ScalarGemm, so nothing breaks when running on a plain JVM. Enable it with:

mvn exec:java                       # .mvn/jvm.config adds --add-modules jdk.incubator.vector
java --add-modules jdk.incubator.vector -cp "target/classes;..." examples.MNISTClassification

Why 4 layers is slower than 2–3

Layers Architecture Params FLOPs/batch ms/epoch
2 layers 784→128→10 101,770 ~32M ~2,600

The 4-layer model has 3.6x more FLOPs than the 2-layer model and adds Dropout (mask generation + element-wise multiply) and gradient clipping overhead per layer. The extra time is purely computational — not a parallelism regression.

For an apples-to-apples comparison on the same architecture, the SIMD GEMM kernels make the current code ~2× faster than the scalar kernels (e.g. 4-layer 13.9s → 6.8s, 3-layer 5.6s → 2.5s in the same measurement window), and far faster than the original single-threaded code.

Full Implementation Examples

2-Layer Model (Keras-matching, fastest)

package examples;

import ml.core.Tensor;
import ml.core.SeedManager;
import ml.network.NeuralNetwork;
import ml.training.*;
import ml.optimizer.SGD;
import ml.loss.CrossEntropyLoss;
import ml.layer.DenseLayer;

public class SimpleBench {
    public static void main(String[] args) throws Exception {
        SeedManager.setSeed(42);

        Dataset trainData = MNISTLoader.load(
            "data/train-images-idx3-ubyte", "data/train-labels-idx1-ubyte");
        Dataset testData = MNISTLoader.load(
            "data/t10k-images-idx3-ubyte", "data/t10k-labels-idx1-ubyte");

        // Keras equivalent: Flatten + Dense(128, relu) + Dense(10, softmax)
        NeuralNetwork network = new NeuralNetwork();
        network.add(new DenseLayer(784, 128));
        network.add(new ml.activation.ReLU());
        network.add(new DenseLayer(128, 10));
        network.add(new ml.activation.Softmax());

        System.out.println(network);

        SGD optimizer = new SGD(0.1);
        CrossEntropyLoss loss = new CrossEntropyLoss();
        Trainer trainer = new Trainer(network, loss, optimizer);

        System.out.println("Training 10 epochs, batch=128...\n");
        long start = System.currentTimeMillis();
        trainer.fit(trainData.images(), trainData.labels(), 10, 128);
        long elapsed = System.currentTimeMillis() - start;
        System.out.printf("\nTraining: %dms (%.0f ms/epoch)%n",
            elapsed, elapsed / 10.0);

        // Evaluate
        int correct = 0;
        int total = testData.images().rows();
        for (int i = 0; i < total; i += 256) {
            int end = Math.min(i + 256, total);
            Tensor batch = testData.images().sliceRows(i, end);
            int[] preds = network.predictBatch(batch);
            int[] labels = java.util.Arrays.copyOfRange(testData.labels(), i, end);
            for (int j = 0; j < preds.length; j++) {
                if (preds[j] == labels[j]) correct++;
            }
        }
        System.out.printf("Accuracy: %d/%d = %.2f%%%n",
            correct, total, 100.0 * correct / total);
    }
}

4-Layer Model (highest capacity, slowest)

package examples;

import ml.core.Tensor;
import ml.core.SeedManager;
import ml.network.NeuralNetwork;
import ml.training.*;
import ml.optimizer.Adam;
import ml.loss.CrossEntropyLoss;
import ml.layer.DenseLayer;
import ml.regularization.Dropout;

public class FourLayerBench {
    public static void main(String[] args) throws Exception {
        SeedManager.setSeed(42);

        Dataset trainData = MNISTLoader.load(
            "data/train-images-idx3-ubyte", "data/train-labels-idx1-ubyte");
        Dataset testData = MNISTLoader.load(
            "data/t10k-images-idx3-ubyte", "data/t10k-labels-idx1-ubyte");

        NeuralNetwork network = new NeuralNetwork();
        network.add(new DenseLayer(784, 256));
        network.add(new ml.activation.ReLU());
        network.add(new Dropout(0.2));
        network.add(new DenseLayer(256, 128));
        network.add(new ml.activation.ReLU());
        network.add(new Dropout(0.2));
        network.add(new DenseLayer(128, 64));
        network.add(new ml.activation.ReLU());
        network.add(new DenseLayer(64, 10));
        network.add(new ml.activation.Softmax());

        System.out.println(network);

        Adam optimizer = new Adam(0.001);
        CrossEntropyLoss loss = new CrossEntropyLoss();
        Trainer trainer = new Trainer(network, loss, optimizer);

        System.out.println("Training 10 epochs, batch=256...\n");
        long start = System.currentTimeMillis();
        trainer.fit(trainData.images(), trainData.labels(), 10, 256);
        long elapsed = System.currentTimeMillis() - start;
        System.out.printf("\nTraining: %dms (%.0f ms/epoch)%n",
            elapsed, elapsed / 10.0);

        int correct = 0;
        int total = testData.images().rows();
        for (int i = 0; i < total; i += 256) {
            int end = Math.min(i + 256, total);
            Tensor batch = testData.images().sliceRows(i, end);
            int[] preds = network.predictBatch(batch);
            int[] labels = java.util.Arrays.copyOfRange(testData.labels(), i, end);
            for (int j = 0; j < preds.length; j++) {
                if (preds[j] == labels[j]) correct++;
            }
        }
        System.out.printf("Accuracy: %d/%d = %.2f%%%n",
            correct, total, 100.0 * correct / total);
    }

06 — Save & Load (Model Persistence)

Models can be saved and loaded in two formats: binary (compact, fast) and JSON (human-readable, debuggable). Both preserve all layer types, weights, and optimizer state.

Binary Format

Uses DataOutputStream with a magic header (mnist-dl/2.0), LITTLE_ENDIAN byte order for double arrays (matching JVM layout), and includes kernel params for Conv2D (kernelSize, stride, padding).

NeuralNetwork net = buildModel();

// Save (weights + optimizer state)
net.saveModel("model.bin");
ModelSerializer.saveOptimizer(optimizer, "opt.bin");

// Load (exact weight match, 0% accuracy loss)
NeuralNetwork loaded = NeuralNetwork.loadModel("model.bin");
Adam loadedOpt = (Adam) ModelSerializer.loadOptimizer("opt.bin");

JSON Format

Human-readable JSON with full weight arrays. Useful for debugging, transfer between languages, or inspecting learned parameters. Layer type uses fully-qualified Java class names.

net.saveJson("model.json");
NeuralNetwork loaded = NeuralNetwork.loadJson("model.json");

Optimizer Persistence

All 5 optimizers (Adam, AdamW, SGD, RMSProp, AdaGrad) save and restore their internal state: momentum buffers, learning rate schedules, and timestep counters.

Two Bugs We Fixed

Bug: Truncated JSON

new FileWriter(f).write(data) without close() left data in an 8KB buffer. For a 2.2MB model, only the first DenseLayer was saved; the rest was silently lost.

Bug: Stale cachedTranspose

Loading weights via System.arraycopy bypassed the update() path, leaving the cached transpose based on random init. Result: 12% accuracy (near random) despite correct weights.

07 — Lessons Learned

Softmax + CrossEntropy

Almost every deep learning framework computes the combined gradient (p - y) / N in the loss, making the Softmax backward a no-op. If you implement them separately, you must decide which one produces the combined gradient — never both.

Parallel != Faster

CompletableFuture overhead (allocation, queue locks, park/unpark syscalls) is 1–5ms per operation. For compute under ~1M operations, sequential code is often faster. Only parallelize when the work clearly exceeds the dispatch cost.

Cached State is Dangerous

Caching the transposed weights saved allocation time but introduced a correctness bug: every optimizer modifies weights in-place, invalidating the cache. Any cached computation derived from mutable state needs an explicit invalidation strategy.

DataLoader Shuffle Bug

When shuffling data, you must use the same shuffled indices for both images and labels. The DataLoader used shuffled indices for labels but sequential sliceRows(start, end) for images — labels never matched their images. Always verify data-label pairing with a simple sanity check.

Parallel Accumulator Race

When splitting work across N threads with ceiling division, you may get >N tasks. Using tid = taskIndex % N to map tasks to accumulators causes two tasks to share one accumulator — a data race. Always size accumulators to the number of tasks, not threads.

Layer Count vs Speed

More layers ≠ slower (at small scale). 2-layer: ~2.6s/epoch, 3-layer: ~2.5s/epoch, 4-layer: ~6.8s/epoch (SIMD GEMM). The 4-layer model has 3.6x more FLOPs — the extra time is purely computational. Once the kernels are SIMD-accelerated, performance tracks FLOPs, not layer count.

Test Gradients Early

A numerical gradient check (finite differences vs. backprop) would have caught the Softmax bug in minutes. Instead we spent hours profiling performance on a model that was fundamentally broken. Always verify correctness before optimizing speed.

Unclosed Writers Lose Data

A FileWriter without close() or try-with-resources may leave data in an 8KB buffer. For a 2.2MB JSON file, only the first ~8KB was flushed to disk — silently truncating the model. Always use try-with-resources for I/O.

External Mutation Breaks Caches

Deserializing weights via System.arraycopy bypasses the layer's update path, leaving cachedTranspose stale. Any cached mutable state must be invalidated by all code paths that modify the source — including serialization.
