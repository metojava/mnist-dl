08 / OPTIMIZATION

Gradient Descent and SGD

How gradients become actual learning.

Gradient descent

Once we know the gradient, we can change a parameter in the direction that reduces the loss.

w ← w − η ∂L/∂w

Here η is the learning rate.

Why subtract the gradient?

The gradient points toward increasing loss. Therefore we move in the opposite direction. 


gradient
   ↑
   |
---●---→ parameter
   |
   ↓
direction of lower loss

Learning rate

The learning rate determines how large each update is.

If it is too small:

  • Training can be extremely slow.

If it is too large:

  • The network can overshoot good solutions.
  • Loss may become unstable.

Our SGD class

public class SGD {

    private double learningRate;

    public SGD(double learningRate) {
        this.learningRate = learningRate;
    }

    public double getLearningRate() {
        return learningRate;
    }
}

Updating a dense layer

double newValue =
    weights.get(i, j)
    - learningRate
    * weightGradients.get(i, j);

weights.set(i, j, newValue);

Every weight receives its own update.

Mini-batch SGD

Instead of calculating gradients using the entire dataset at once, we split the training data into small batches. 


60,000 training images

        ↓

batch 1: 32 images
batch 2: 32 images
batch 3: 32 images
...

After processing one batch, the weights are updated.

Why mini-batches?

  • They require less memory.
  • They make training computationally manageable.
  • They provide frequent parameter updates.
  • The noise in the gradient can sometimes help optimization.
Key idea: Backpropagation calculates "which way should we move?" Gradient descent decides "how far should we move?"
